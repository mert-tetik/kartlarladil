# Google Play Data Safety Guide

This guide helps you fill out the **Data safety** section in Google Play Console for the FoxiesDeck Trusted Web Activity (TWA).

## Account creation and deletion declarations

Google Play requires you to declare whether your app supports in-app **Account creation** and **Account deletion**.

FoxiesDeck supports both:

- **Account creation**
  - Routes: `/register`, `/login`, `/register/preferences`.
  - Methods: email + password, or Google OAuth (`signInWithGoogleAction`).
  - User identity is managed by Supabase Auth.

- **Account deletion**
  - Route: `/account/settings`.
  - Component: `DeleteAccountForm` (`src/features/auth/components/delete-account-form.tsx`).
  - The user must type a confirmation phrase and cannot delete while an active subscription exists.
  - Deletion is handled by `deleteAccountAction` (`src/features/auth/actions.ts`), which uses the Supabase admin client to remove the auth user and cascades to `user_profiles`, `user_cards`, `practice_attempts`, and other user-owned rows.

In Play Console, enable both:

```
Account creation → Yes
Account deletion → Yes
```

## Data collected

The following data types are collected or linked to the user account:

| Data type | Purpose | How it is collected | User control |
|-----------|---------|---------------------|--------------|
| Email address | Authentication, account recovery, transaction receipts | User enters it during registration; or provided by Google OAuth | Visible in `/account/settings`; deletion removes it |
| User ID (Supabase UUID) | Identify the user across devices and sessions | Generated by Supabase Auth at sign-up | Cannot be changed; removed on account deletion |
| App interactions | Improve features, enforce plan limits, track learning progress | Generated as the user uses the app (quiz answers, card draws, AI usage) | Stored in `user_cards`, `practice_attempts`, `ai_usage_events`; removed on account deletion |
| Device or other identifiers | Analytics, debugging, subscription validation | Firebase Analytics, Google Play Billing purchase tokens | Limited to platform-provided identifiers; no extra device fingerprinting |
| Purchase history | Restore subscriptions, verify entitlements | Google Play Billing or Lemon Squeezy webhooks | Stored in `user_subscriptions`; removed on account deletion |

## Sensitive data

FoxiesDeck does **not** intentionally collect:

- Precise location
- Contacts
- Photos, videos, or audio recordings (microphone is used only for speech recognition in the browser and is not stored)
- Health or financial information beyond purchase history

## Encryption

- All traffic is served over HTTPS.
- Supabase Auth stores passwords with bcrypt.
- Service-role keys and API keys are kept server-side only.

## Additional Play Console settings

- **Data safety → Data encryption in transit** → `Yes`
- **Data safety → Data deletion** → link to `/account/settings` or your privacy contact
- **Privacy policy** → link to `/privacy` on your production domain

## Verification checklist before publish

- [ ] Account creation is declared as `Yes`.
- [ ] Account deletion is declared as `Yes`.
- [ ] Email address and User IDs are listed under collected data.
- [ ] App interactions and Purchase history are listed if the form asks for them.
- [ ] Privacy policy URL points to a live `/privacy` page.
- [ ] `/account/settings` loads and shows the Delete account section for a logged-in user.
